## Coding Challenges/Practices

**(Suggested Start: The Sooner The Better)**

By practicing coding challenges it will benefit you in:
- Projects and career, as you will improve your coding skills, hands-on, little by little
- The later interview stages have coding assessments and live coding
- Often the platforms you will practice on, you can either get noticed or receive certificates that you can use to optimize your portfolio (A future module)
- How to build a habit

**WHEN?** It doesn’t matter when, as long as you do them. The ideal time would be a time you can do it every day consistently when you are not tired; such as the first thing after you wake up.

Remember it takes 21 days to turn something into a habit. When first trying these assessments, they can be pretty scary to do but with practice, we will reap the rewards.

Start easy (Hackerrank is great for confidence-boosting), then once you pass most under 30 mins, increase the difficulty.

If we are struggling with easy, that’s great we found something we need to improve. This tells us we need to keep working on the challenges and with persistent and consistent practicing we will improve!

I would suggest spending some time each day to learn more about Python or coding to work our way up to the challenges. I still do this every day.

**NOTE: **View [Learning paths](https://docs.google.com/document/u/0/d/1bol1mA3OLtGlHrRPHwZHYeSDEQEW6l8ZUNvhtT4WaGo/edit) for more info

I know these assessments may seem pointless to do when you feel like you still have lots of “data science” concepts to learn and I get that, I felt the same. The mind shift that helped me was not focusing on passing but if I learned something instead. You can always learn something from your failures (even if that includes looking at the answer).

One comment I want to add is that the data science interview testing standards are still not perfect and sometimes the tests are not really a fair representation of the work you do.  **NOTE**: Any question that says, you “have” to do it this way or you can’t use libraries or Python tricks is more tailored to developers or software engineers, but you can think of those questions as learning more about the fundamentals of coding.

If you wanted to practice your coding while learning data science too I would do the data science-based coding assessments.

**WHERE?**  There are many places to do challenges. These are my top 3, see the link for my reasons.

My personal preferences:
- [Hackerrank](https://www.hackerrank.com/) - I prefer this and there are certificates you can add to your LinkedIn/Resume (2 birds, one stone) It also has data science-related topics.
- [Leetcode](https://leetcode.com/) - Lots of examples

Any of these are great choices, remember every little step is one step closer to your goal!

BONUS: Here is a great [article](https://medium.com/@aryannayakk/one-year-of-consistent-leetcoding-everyday-5d070d1c590a) about making Leetcode a consistent habit.

**NOTE: **These coding assessments appear in the more coding-heavy positions, such as Machine Learning Engineer, Data Engineer, MLOps Engineer and the bigger companies for data scientist roles.

## [Markdown](https://www.markdownguide.org/basic-syntax/) or other documentation methods

**(Suggested Start: The sooner the better)**

If you are not familiar with Markdown, it is the “Text” cells in jupyter notebooks.

Markdown is very easy to learn and is not just done at the end of the project. It will also save you time if you write notes for your project to remember where you left off if you are not going to be touching it for a couple of days.

Remember it takes someone on average 12 seconds to make a first impression. Thus, if the first thing they see in your project is a beautiful in-depth README then they will look into the project more. Now think, what would happen if they see a messy or no README on your project? Would they even spend another second looking at your project? It shows the effort you put into the little things!

It is better to have a “so-so” project with a great README than a great project and no README.

Think of Markdown as presenting your communication with outsiders (including non-tech related people)

READMEs often tell the story and show the inference. Remember the inference from the project, either good or bad is the most important part.

Another positive reason to learn markdown, a lot of messaging platforms have this embedded into the message to be able to clearly communicate your project (E.g. Slack, Webex, Discord, Github and many more). Since these platforms are how you communicate in the industry, you can think of learning Markdown as improving your communication as well.

**TIP:** I highly suggest whenever you are taking notes use Markdown and try to add the VSCode extension “markdownlint” it will help you practice the markdown standards. ( You can see an example in [python notes](https://drive.google.com/file/d/1hfz9cElpWLQ-5vVqwf0IQOPtR_x-Kyr4/view?usp=sharing))
- “What should I learn in markdown?”:
  - Different levels of heading
  - Links
  - Images
  - Code blocks (inline or
  - Gif
  - Tables
  - Project structure trees

If interested in an additional read [8 Guidelines to Create Professional Data Science Notebooks](https://towardsdatascience.com/8-guidelines-to-create-professional-data-science-notebooks-97572894b2e5)

## Integrated Development Environment (IDE) **(Suggested Start: Week 2)**

**Why use IDEs?**

**Short Answer:** You will become more efficient in data science.

**Long Answer:** Using a Jupyter server or Colab is great for quick small experiments but for ML in production and longer projects you will need production-ready code with application-level skills. It also makes you stand out from other entry-level data scientists. It may seem like a larger learning curve or not worth it in the short term but it will save you LOTS of time in the long term.

**What do I need to learn in IDE?**
- Complex file structures
- Directories (current working directory, parent, child)
- Relative vs absolute paths
- All Git practices
- Terminals
- Using conda/python environments within IDE
- Visualizing your data
- Visualizing docs
- Testing/viewing markdown/latex/HTML docs
- Debugging (Breakpoints, tracking variables and environment)
- (Intermediate) Connecting to remotes or containers

My suggestion would be [Microsoft VSCode](https://code.visualstudio.com/download) feel free to use any other IDE, I like VSCode because I can do any language coding, while also viewing data, pdfs, databases, containers and my other awesome features

Suggested Extensions to install:
- Python
- Pylance
- Jupyter
- Data Preview
- GitLens
- Markdown All in One
- Markdownlint - Will help you practice the standards for markdown
- (Intermediate) Remote Development
- (Intermediate) Docker
- Vscode-pdf - to view pdf in VSCode, great for producing results from academic papers

## **Practicing Screening/Behaviour Interview Questions (Suggested Start: Week 5)**

**This will be **[discussed in Module 5](https://docs.google.com/document/d/1IOQ1smQLmFEX9Sn29WkKKqEGO8Whrr19xSbowaXqIW8/edit?usp=sharing)
- Practice each day
- Do this when you are doing mindless things (E.g. dishes, laundry, etc)

**The most important questions**

- “Tell me about yourself?” (Or some variation)
- “Why are you interested in us?” (Or some variation)
- [“What is your expected salary?”](https://docs.google.com/document/u/0/d/17egf3yuZuMV4HYnATloUzwJmF80DdEMrzF93Gog2q4w/edit) (Or some variation)
- “Can you tell me about a project you have done?” (Or some variation)

**How to practice**
- Choose a question
- Write down your main points in bullets (or full sentences if you would like)
- Ask yourself the question, then answer it (Yes, talk to yourself lol)
- Get a loved one or someone who will give their honest opinions, then get them to ask you
- Record a video of yourself answering the question, critique it (don’t be too hard on yourself remember the 3:1 positive:negative ratio) then improve it.
- Record it on [Interview Warmup - Grow with Google](https://grow.google/certificates/interview-warmup/) and get feedback (save that feedback in your interview [script document](https://docs.google.com/document/u/0/d/1VxfE474N5r-2PGtqhD5zVkOcIulBHQ7CT0fB-q3nOes/edit))
- (Optional) Send the video to a mentor for additional feedback

**GOAL: **Practice 10 mins a day. If you spend 6 days (one for each step) for ten mins, you will feel much more confident and you won't just memorize it.

## BONUS: Interest Outside of Courses

**(Suggested Start: The sooner the better)**

**WARNING**: Limit the information you take in, if you are learning about the industry, learn something that you are currently working on. For example if you are working on fundamentals of Python don’t read how LLMs are used in the industry, learn about how python is used in the industry.

You will find when you don’t have experience, interviewers will ask you “how do you stay up to date with new data science material or news?”

This question is to find out how passionate you are in the field.

Just because you don’t know every model or breaking news about AI **doesn’t** mean you are not passionate!

This will help you understand some of the fundamentals of data science more and to stay relevant in the industry.

Remember, just learning or watching it won’t help you in the long run, you must try to use the knowledge in a project or teach someone else

It is easy to get overwhelmed so if you feel like that, take a step back and ask yourself “Why do I feel overwhelmed and what can I do right now to not feel like this?” and see if you can find a solution to it.

**TIP: **Follow influencers in the domain, field, industry or sector you’re passionate about on social media or email newsletters

“How do I stay up to date?”

- Email newsletter
- Social media
- Community
- Academic papers
- Podcasts

**GOAL:** Read 1 article or listen to a podcast while doing mundane tasks once a day

## BONUS: Grasping the ML fundamentals (Suggested Start: As soon as you learn any model)

This will be really beneficial for you for the bigger companies or the job titles that require more software engineering such as Data Data Scientist or Machine Learning Engineer.

A good grasp of ML fundamentals—is to have them write up some important ML algorithms (LR, KNN, SVM, etc.) at 4 levels of abstraction:
- Be able to explain it to a layman
- Be able to explain to an ML practitioner
- Implement it in code (with sklearn)
- Implement it with custom code (with NumPy)

Then research and study the top 25 interview questions on all the 10 popular algorithms namely Linear regression, logistic regression, SVM, decision trees, random forest, naive Bayes, PCA, XGboost and lightGBM. In the Interview module, you will have a lot more questions, there is an [Extra Resources](https://drive.google.com/drive/folders/1iwFDSMYu5Vv4_BMFHEGE6QKfw38PB4fC?usp=sharing) directory with lots of practice interview questions.
