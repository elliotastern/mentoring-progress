# Terms:

Before we get started, let’s define some common terms

- Full-Stack Project** - The term “full-stack” comes from software where you have the *front-end**** ***where it’s focused on the user interface (UI) and user experience (UX), meaning features that the user uses. Where the *backend *refers to the parts of the application that the user doesn’t use (ie database). Thus, a full-stack project means we have a small product that our user (who doesn’t know data) can interact with and it runs systematically.

- End-to-end Project - **This is often interchanged with “Full-stack Project” in our mentorship but to note, outside our mentorship, it is often considered for a project from data collection to results which can be done in a notebook. Yes, this can be true but our goal is to separate the User experience and the technical work.

- Industry Project** - We define this by combining technical skills and soft skills. For example, we will take this Full-stack project, and teach you how to interact with teammates, git procedures, project planning, stakeholders presentations and business reports to show impact.
# Intro: Why Build A Full-Stack Project?

In the realm of data science, machine learning and other problem-solving roles, success extends beyond technical skills but also the constant navigation of decisions.
From pivotal choices like algorithm selection to seemingly inconsequential ones like function naming, the daily landscape involves a multitude of judgments. We will be honing decision-making skills through practical experience, particularly by constructing end-to-end projects treated as real problem-solving products.
The narrative underscores the significance of trade-offs and learning from mistakes, contending that mistakes become valuable learning opportunities. The advantage of accumulating experience before entering the job market, highlighting that the stories of challenges and lessons learned from building projects serve as powerful narratives in interviews.
Acknowledging the initial challenge of choosing the "best" tools, remember action is superior to inaction, encouraging beginners to start with familiar tools and learn through hands-on experience.
It is valuable for a few reasons:
## 1. Building is one of the best ways to learn

Between collecting and cleaning data, training a model, and deploying it, there are so many hidden lessons that you would never encounter in Kaggle competitions, or notebooks. As a mentor, we can guide you on what tools to use and where to look for information. We can also provide valuable context on how these things are done in the industry. Hence the name *Industry-like Project.*
## 2. Attract Potential Employers

Experience stands out as the most powerful indicator on a resume. A well-curated portfolio serves as a compelling showcase of one's competence. However, it is essential to recognize that a roster of minor, uniform projects lacks the impact of a singular, meticulously developed project. The latter, demanding sustained effort and adept problem-solving, proves more valuable. Conceiving the project as a product enhances the mentee's ability to approach and resolve challenges for actual individuals, steering away from the tendency to view every problem through the lens of a deep learning hammer.
## 3. Why Industry-Like Skills

There are many skills you will learn on the job, that universities and Bootcamps don’t teach you. We will gain those skills to allow you to hit the ground running when you land that next role to fast-track your career to more senior roles, promotions or your next job search. Some of these include:
- Communication to manager (ie standup)
- Software Development Lifecycle (ie code review)
- Project Management
- Client Management (ie Minimal Viable Product)
- Business Reports
- Stakeholder Presentations
- Etc
